# project-me-config

The GitOps repository for **project-me**. Flux on a single k3s server reads `main` and deploys three
services:

| Service | What it is | Served at |
|---|---|---|
| frontend | Next.js public website | `https://<domain>` |
| cms-admin | CMS admin SPA (nginx) | `https://admin.<domain>` |
| cms-api | CMS backend (Bun + Prisma, Postgres outside the cluster) | `https://api.<domain>` |

The application code and images live in the app repository. This repository only says what runs
and with which image tag. It contains no project values or secrets: names, domains and credentials
are on the cluster.

## Architecture

```
Request path

  browser ──DNS──► VPS :80/:443
                    │
                    ▼
                  Traefik (k3s bundled)      http → https redirect (Middleware)
                    │                         TLS certs from cert-manager
      ┌─────────────┼──────────────────┐
      ▼             ▼                  ▼
  <domain>     admin.<domain>     api.<domain>        Ingress hosts
      │             │                  │
  Service       Service            Service           ClusterIP
      │             │                  │
  frontend pod  cms-admin pod      cms-api pod ──► Postgres (external)
      └──────── in-cluster ───────────►┘
                (frontend server → cms-api)

Deploy path

  app repo pipeline ──push image──► GHCR
          └──commit APP_IMAGE_TAG──► this repo (main)
                                        │ polled every 1m over SSH (deploy key)
                                        ▼
                               Flux GitRepository flux-system
                                        ▼
                     Kustomization flux-system  (./cluster/me)
                        ├─► project-me-cms-api-sync-prod   ─► apps/cms-api
                        ├─► project-me-cms-admin-sync-prod ─► apps/cms-admin
                        └─► project-me-frontend-sync-prod  ─► apps/frontend
                              names from ${APP_NAME}/${APP_ENV} in shared-config (root substitution)
                              ${APP_*} filled from the shared + per-app ConfigMaps in flux-system
```

## Layout

```
apps/
  cms-api/                  Deployment (with a migration init container) + Service + Ingress + Middleware
  cms-admin/                Deployment + Service + Ingress + Middleware
  frontend/                 Deployment + Service + Ingress + Middleware
cluster/me/
  kustomization.yaml        what the root Flux Kustomization applies
  flux-system/              generated by `flux bootstrap` (gotk-*.yaml); don't edit by hand
  <svc>-sync.yaml           one Flux Kustomization per service; holds APP_IMAGE_TAG
templates/
  shared-configmap.example.yaml   ${APP_*} values all three apps use; also names the sync files (before bootstrap)
  <svc>-configmap.example.yaml    per-app ${APP_*} values (3, applied by hand to flux-system)
  *-secret.example.yaml     runtime Secrets for cms-api and frontend (applied by hand)
docs/                       audit, component docs, deployment guide
.gitignore                  keeps filled-in templates/*.yaml out of git
```

## Quick start

Starting from an empty server: install k3s and cert-manager, set up DNS, apply the shared ConfigMap,
run `flux bootstrap` with `--path=cluster/me`, then apply the namespace, three per-app ConfigMaps and
two Secrets by hand.
Follow [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) step by step.

## Validating a change

There's no CI in this repository, so render every app before pushing to `main`:

```bash
kubectl kustomize apps/cms-api
kubectl kustomize apps/cms-admin
kubectl kustomize apps/frontend
kubectl kustomize cluster/me
```

With the `flux` CLI installed, also render an app with the variable substitution applied:

```bash
flux build kustomization project-me-cms-api-sync-prod \
  --path ./apps/cms-api --kustomization-file ./cluster/me/cms-api-sync.yaml --dry-run
```

Anything pushed to `main` is applied to the cluster within a few minutes.

## Rules

- **No secrets or project values in git.** Manifests use `${APP_*}` placeholders only. Filled-in
  copies of `templates/*.example.yaml` are gitignored. Apply them with `kubectl apply --server-side`.
- **Image tags come from the app repository.** Its pipeline rewrites the one line starting with
  `APP_IMAGE_TAG:` in `cluster/me/<svc>-sync.yaml`. Keep exactly one such line per file
  ([contract](docs/components/configuration.md#image-tag-contract-with-the-app-repository)).
- **Don't rename resources, labels or `${APP_*}` inputs on a live cluster** without a plan. Flux
  prunes the old names, and the hand-made namespace and Secrets have to be recreated.
- **Don't edit `cluster/me/flux-system/gotk-*.yaml` by hand.** Re-run `flux bootstrap`
  ([Upgrading Flux](docs/DEPLOYMENT.md#13-upgrading-flux)).
